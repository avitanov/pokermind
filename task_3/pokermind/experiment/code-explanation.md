# `experiment/` — top-level orchestration for observation hands and crash-recoverable tournament runs

This subpackage is the outermost driver of PokerMind. It runs a single agent-driven observation hand, runs or resumes a single full tournament (writing a snapshot after every decision and running an idempotent Judge phase), runs the fixed three-tournament final experiment, guards every entry point with an OpenRouter credential preflight, and applies a deterministic integration gate to completed results. It coordinates the `agents`, `engine`, `evaluation`, `results`, and `observability` subpackages; the LLM/network work itself lives in those packages, invoked from here.

## Files

### `runner.py` — orchestrates play, resume, judging, and the multi-tournament loop
- `run_observation_hand(tournament_id, seed, initial_button, telemetry_client=None) -> tuple[TournamentState, dict]` — runs one real agent-driven hand through the production decision path. Calls `_preflight_openrouter()` (network), builds player agents, creates the tournament state and result, and plays exactly one hand with no file I/O (output directory is `None`, so no snapshots). Makes LLM calls per decision.
- `run_one_tournament(tournament_id, seed, initial_button, output_directory, telemetry_client=None) -> tuple[TournamentState, dict, Path]` — runs one fresh tournament end to end: preflight, build agents, create fresh state/result, then delegates to `_continue_tournament`. Writes snapshots and JSON output; makes LLM calls for play and judging.
- `resume_tournament(snapshot_path, output_directory=None, telemetry_client=None) -> tuple[TournamentState, dict, Path]` — continues a failed or interrupted tournament from its atomic checkpoint. Preflights, loads the snapshot, restores runtime state, prepares the resumed result, decides whether the current hand is mid-play (`resume_active_hand` when a `current_hand` exists and is not completed), rebuilds agents, and delegates to `_continue_tournament`. Defaults the output directory to the snapshot's parent.
- `run_or_resume_tournament(tournament_id, seed, initial_button, output_directory, telemetry_client=None) -> tuple[TournamentState, dict, Path]` — the idempotent entry point. If `tournament_{id}.json` (completed file) exists, it validates saved identity, calls `_ensure_judge_evaluations` to self-heal a crash that interrupted judging before validation, validates the completed result, and returns without replaying the hand. Else if `tournament_{id}.in_progress.json` exists, it validates identity and calls `resume_tournament`. Otherwise it starts fresh via `run_one_tournament`.
- `run_final_experiment(base_seed, output_directory, telemetry_client=None) -> tuple[list[Path], dict, Path]` — runs the fixed three isolated tournaments. Iterates `initial_button` over `(0, 1, 2)` with `seed = base_seed + index` and id `final_{index+1}_{seed}_button_{initial_button}`, calling `run_or_resume_tournament` for each; raises `RuntimeError` if any did not complete. Then builds and writes an experiment summary aggregating the three tournament JSON files, returning the per-tournament paths, the summary dict, and the summary path.
- `_continue_tournament(state, result, player_agents, output_directory, telemetry_client, *, resume_active_hand=False) -> tuple[TournamentState, dict, Path]` — the shared play loop used by both fresh and resumed runs. Writes an initial snapshot, then loops while the tournament is IN_PROGRESS: raises `TournamentLimitError` if `hands_completed >= MAX_TOURNAMENT_HANDS`, plays one hand via `_play_one_agent_hand` (passing `continue_current_hand` only on the first resumed iteration), and on a FAILED status finalizes the failed tournament, flushes observability, and returns early. If the loop ends in any status other than COMPLETED it finalizes as failed and returns. On COMPLETED it finalizes the result, snapshots, runs `_ensure_judge_evaluations`, applies `validate_completed_result`, flushes observability, and returns the final snapshot path.
- `_play_one_agent_hand(state, result, player_agents, output_directory, telemetry_client, *, continue_current_hand=False) -> Path | None` — plays a single hand. With `continue_current_hand` it requires an active (non-completed) `current_hand` and raises `ValueError` otherwise; else it starts a new hand and records its start. Snapshots (when an output directory is given) after start, then loops: for each pending actor it coordinates one decision via `coordinate_decision` (LLM call through `invoke_player_once`), increments the action counter unless the API failed, records the decision, snapshots, checks chip invariants, and returns early on API failure; when a betting round is complete it advances the street; on hand completion it increments `hands_completed`, records completion, and snapshots. Returns the latest snapshot path (or `None` when no output directory).
- `_ensure_judge_evaluations(result, output_directory, telemetry_client) -> Path | None` — idempotent Judge phase. Computes the players still pending via `_completed_judge_players`; if none are pending it returns `None` immediately (so an offline rerun of a fully judged tournament makes no network calls). Otherwise it preflights OpenRouter, creates the Judge agent, and for each pending player runs `evaluate_player` (LLM call via `invoke_judge_once`), appends the evaluation, and snapshots. Returns the latest snapshot path, or `None` if nothing was pending.
- `_completed_judge_players(result) -> set[str]` — returns the set of player names whose `judge_evaluations` entry has `status == "completed"`; returns an empty set when the field is missing or not a list.
- `_finalize_failed_tournament(result, state, output_directory) -> Path` — finalizes the result as failed (stamping `completed_at`) and writes a final snapshot, returning its path.
- `_validate_saved_identity(result, tournament_id, seed, initial_button) -> None` — raises `ValueError` if a loaded snapshot's `tournament_id`, `seed`, and `initial_button` do not match the requested run.

### `validation.py` — external preflight and completed-tournament integrity gate
- `ExperimentPreflightError(RuntimeError)` — raised when the fixed external model configuration is unusable before dealing (missing key, failed credential check, free tier, or exhausted credits).
- `_utc_now() -> str` — returns the current UTC time as an ISO 8601 string (used to stamp start/finish times).
- `_preflight_openrouter() -> None` — network credential preflight. Requires `OPENROUTER_API_KEY` in the environment, then GETs the OpenRouter key endpoint (`https://openrouter.ai/api/v1/key`, 10s timeout) with a Bearer header. Raises `ExperimentPreflightError` on missing key, HTTP error, transport/parse error, invalid payload, a free-tier account, or a non-positive `limit_remaining`. Makes one HTTP request.
- `validate_completed_result(result) -> TournamentState` — the deterministic portion of the one-tournament integration gate; raises `AssertionError` on any violation. Requires status COMPLETED, replays the tournament via `replay_tournament` and asserts final stacks are exactly `TOTAL_CHIPS/0/0`, checks hands exist with consecutive `hand_number`s and that each hand's ending stacks sum to `TOTAL_CHIPS`, checks every recorded decision has the required fields and (unless `api_failed`) executed a legal action, asserts adaptive `peek_opponent_card` succeeded at most once across the run, requires exactly one completed Judge evaluation per player, and calls `compact_player_trace` for each player. Returns the replayed `TournamentState`. No network calls.
- `_decision_matches_legal_action(decision) -> bool` — helper used by the gate; returns whether a decision's `final_executed` action/amount matches one of its recorded `legal_actions` (exact amount when the legal action fixes one, otherwise within `[min_amount, max_amount]`).

### `__init__.py` — public production experiment orchestration API
- Re-exports the runner entry points (`run_final_experiment`, `run_observation_hand`, `run_one_tournament`, `run_or_resume_tournament`, `resume_tournament`) and the validation surface (`ExperimentPreflightError`, `_preflight_openrouter`, `validate_completed_result`) via `__all__`. No logic of its own.

## How it fits together

A tournament is played hand by hand, and `_play_one_agent_hand` writes a fresh snapshot after every single agent decision (and at hand start/completion). If the process crashes mid-play, the last snapshot is a durable checkpoint: `resume_tournament` reloads it, detects an unfinished current hand, and continues exactly where it stopped. Once all hands are played, the tournament status flips to COMPLETED, the result is finalized, and the snapshot is renamed to the completed `tournament_{id}.json` file. Only then does the Judge phase run, and it is idempotent: `_ensure_judge_evaluations` evaluates only players not yet marked `completed` and returns without any network call when everything is already judged — so a crash between play and judging is repaired by finishing just the missing evaluations rather than replaying the hand. `run_or_resume_tournament` encodes this by reusing a completed file (self-healing its Judge phase before the integration gate), resuming an in-progress checkpoint, or starting fresh. `run_final_experiment` loops that entry point over the three fixed tournaments, so a crash anywhere in the batch re-enters via reuse/resume and never re-spends already-paid LLM calls.
