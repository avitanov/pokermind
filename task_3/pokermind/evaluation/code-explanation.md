# `evaluation/` — LLM-as-Judge scoring of a player's tournament decisions

This subpackage takes a completed tournament record and produces an independent, structured quality assessment of a single player. It first distills that player's history into a compact, visibility-safe trace (only what the player could see at each decision, no hidden cards and no reward/penalty for lucky outcomes), then invokes a separate Judge LLM constrained to a strict `JudgeEvaluation` schema. Invocation is bounded to at most two attempts with per-attempt error categorization, and the returned record never mutates its inputs.

## Files

### `traces.py` — build a compact, visibility-safe Judge input from raw tournament JSON
- `compact_player_trace(tournament_json: dict[str, object], player: PlayerName) -> dict[str, object]` — Extracts only the named player's decisions into a compact trace. Requires `status == "completed"` (raises `ValueError` otherwise). For each decision the player actually executed (`final_executed` present), copies only that decision's recorded `visible_state` — position (derived from seat), own hole cards, board, pot, per-player stacks, legal actions, tool events, the executed action, and `retry`/`fallback` flags. Also attaches an `eventual_outcome` block (`won_hand`, `chips_awarded`, `ending_stack`) that the prompt explicitly instructs the Judge not to use for reward/penalty. Adds tournament id, player name, `strategy_summary` (from `strategy_prompt_summary`), `tool_usage_applicable` (true only for `PlayerName.ADAPTIVE`), and the player's metrics. Raises `TypeError`/`ValueError` on malformed or empty data. No LLM/network calls.
- `render_judge_prompt(compact_trace: dict[str, object]) -> str` — Serializes the compact trace to deterministic, minified JSON (`sort_keys=True`, compact separators). This is the entire user prompt; raw tournament JSON is never passed. No LLM/network calls.
- Private helpers: `_player_seat` (finds the one matching seat), `_position_name` (maps seat to button/small_blind/big_blind or "other"), `_compact_legal_actions` (drops `None` values), `_compact_tool_events` (keeps only tool/input/result).

### `schemas.py` — strict structured-output contract and per-attempt bookkeeping types
- `MAX_JUDGE_ATTEMPTS = 2` — hard cap on Judge invocations per player.
- `JUDGE_INVOCATION_LIMITS` — plain dict `{turns: 2, output_tokens: 1400, total_tokens: 12000}`; `output_tokens` caps the request's `max_tokens`, and the dict is also shown in the notebook. (No longer a Strands `Limits` type.)
- `ScoredRationale` (pydantic, `extra="forbid"`) — `score: int` (1-10, strict) and `rationale` (stripped, 1-500 chars, strict). One bounded score plus its concise observable justification.
- `ToolUsageEvaluation` (pydantic, `extra="forbid"`) — `applicable: bool`, optional `score: int | None` (1-10), `rationale`. A `model_validator` enforces that `score` is present exactly when `applicable` is true.
- `DecisionReference` (pydantic, `extra="forbid"`) — `hand_number: int` (>=1), `street: Street`, `explanation` (rationale). Points at one evaluated decision without reproducing private state.
- `JudgeEvaluation` (pydantic, `extra="forbid"`) — the required Judge output: `decision_quality`, `strategy_consistency`, `adaptation`, `reason_quality` (each a `ScoredRationale`), `tool_usage` (`ToolUsageEvaluation`), `overall_score: int` (1-10), `strongest_decision` and `weakest_decision` (each a `DecisionReference`), and `main_improvement` (rationale).
- `JudgeOutputError(ValueError)` — raised when a Judge response fails its structured contract (used for validation-level failures).
- `JudgeAttemptRecord` (`@dataclass(slots=True)`) — sanitized record of one attempt: `attempt: int`, `category: str`, `error: str | None`, `usage: dict`, `retry: bool`.

### `judge.py` — bounded independent Judge invocation, validation, and result assembly
The Judge is a single stateless call, so it talks to OpenRouter through the **OpenAI SDK directly** (no Strands agent).
- `create_judge_client() -> OpenAI` — **LLM/network config.** Builds the OpenRouter `OpenAI` client (`base_url`, `OPENROUTER_TIMEOUT_SECONDS`, `max_retries=0`). Raises `RuntimeError` if `OPENROUTER_API_KEY` is unset. No call is made here.
- `invoke_judge_once(client: OpenAI, prompt: str, attempt: int) -> ParsedChatCompletion[JudgeEvaluation]` — **LLM/network call.** One `client.chat.completions.parse(...)` with `response_format=JudgeEvaluation` (schema-constrained structured output), `temperature=0.1`, `max_tokens` from the limits, and reasoning excluded. Transient API errors propagate to the caller; `LengthFinishReasonError`/`ContentFilterFinishReasonError` are caught and their `.completion` returned so truncation/filtering is handled as a retryable structured-output miss. (`attempt` is unused.)
- `evaluate_player(tournament_json, player, invoke_once, telemetry_client: Langfuse | None = None) -> dict[str, object]` — **Drives the LLM (via the injected `invoke_once`).** Orchestrates up to `MAX_JUDGE_ATTEMPTS` attempts; see flow below. Returns a non-mutating result record with `status` `"completed"` or `"failed"`, serialized attempts, combined usage, the evaluation (or `None`), and an error block on failure. Each attempt runs inside a `judge_attempt_scope` observability span.
- Error categories recorded per attempt:
  - `"api_failure"` — any `openai.APIError` (throttling, timeouts, or a rejected request), caught in one branch so the tournament fails gracefully rather than crashing; logged at level `ERROR`.
  - `"structured_output"` — a truncated/filtered completion or a `JudgeOutputError` from validation (level `WARNING`).
  - `"success"` — accepted evaluation.
- Private helpers: `_validate_evaluation` (reads `choices[0].message.parsed`, falling back to `JudgeEvaluation.model_validate_json(content)`; rejects `finish_reason` of `length`/`content_filter`; then enforces two anti-leak invariants: `tool_usage.applicable` must match whether the player is `ADAPTIVE`, and both `strongest_decision`/`weakest_decision` must reference a `(hand, street)` pair present in the compact trace — otherwise raises `JudgeOutputError`); `_judge_usage` (reads `completion.usage` into the normalized token dict); `_unavailable_usage` (usage placeholder when no tokens observed); `_combined_usage` (sums token usage across attempts that reported it); `_serialize_attempts` (turns `JudgeAttemptRecord`s into plain dicts).
- `_JUDGE_PROMPT` — the system prompt that encodes the rules: judge only observable decisions and stated reasons, use only state visible at decision time, never infer hidden/future cards or private reasoning, never reward/penalize based on lucky or unlucky outcomes, score consistency against the supplied strategy summary, treat tool usage as applicable only when the input says so, and return only the structured fields.

### `__init__.py` — public API surface
- Re-exports the client/invocation functions (`create_judge_client`, `invoke_judge_once`, `evaluate_player`), the trace builders (`compact_player_trace`, `render_judge_prompt`), the schema types/constants (`JudgeEvaluation`, `ScoredRationale`, `ToolUsageEvaluation`, `DecisionReference`, `JudgeAttemptRecord`, `JudgeOutputError`, `JUDGE_INVOCATION_LIMITS`, `MAX_JUDGE_ATTEMPTS`) via `__all__`.

## How it fits together

`evaluate_player` is the entry point. It first calls `compact_player_trace(...)` to reduce the full tournament record to only the target player's observable, decision-time state (no opponent hole cards, no future board), then `render_judge_prompt(...)` to serialize that trace into deterministic minified JSON — the raw tournament JSON is never sent to the model. It then loops up to two attempts: each attempt opens a `judge_attempt_scope` telemetry span and calls the injected `invoke_once` (normally `invoke_judge_once`, one stateless OpenAI-SDK `chat.completions.parse` call against OpenRouter). The completion's parsed structured output is validated by `_validate_evaluation` against the strict `JudgeEvaluation` schema plus two anti-leak invariants (tool applicability must match the player role; strongest/weakest decisions must reference decisions that actually exist in the compact trace). On success it returns a `status: "completed"` record with the evaluation and combined token usage; each failure is categorized (`api_failure` or `structured_output`) and retried if attempts remain, and after both attempts fail it returns a `status: "failed"` record carrying the final category. The Judge deliberately runs on a different model family than the players (`JUDGE_MODEL_ID = "google/gemini-3-flash-preview"` vs. the players' `PLAYER_MODEL_ID = "deepseek/deepseek-v4-flash"`) to keep evaluation independent, and the `_JUDGE_PROMPT` plus the trace's visibility-safe construction jointly enforce the no-hidden-information and anti-outcome-bias rules (the `eventual_outcome` field is included only for context and explicitly excluded from reward/penalty).
