# `agents/` — LLM poker players (Conservative / Aggressive / Adaptive) on the Strands framework

This subpackage turns a `TournamentState` and an acting seat into one legal, validated poker action produced by an LLM. It owns model/agent configuration, the information-isolated "visible state" a player is allowed to see, the two Adaptive-only information tools, structured-output parsing plus deterministic poker validation with bounded retries, the decision coordinator that drives the retry/fallback loop, and the direct single-attempt dispatch that invokes the acting player's agent. It sits between the deterministic `engine`/`core.domain` (which it reads and mutates only through validated actions) and the `observability` layer (which it wraps every attempt in).

## Files

### `configuration.py` — shared OpenRouter model plus the three strategy agents
- Module constants: `OPENROUTER_BASE_URL`, `PLAYER_PROVIDER_ROUTING` (pins provider to `cloudflare`, no fallbacks), `OPENROUTER_TIMEOUT_SECONDS` (60s), `PLAYER_INVOCATION_LIMITS` (`turns=4`, `output_tokens=2000`, `total_tokens=12000`), `MAX_DECISION_ATTEMPTS` (6), fallback reason strings, and `_LIMIT_STOP_REASONS` (stop reasons treated as invocation-limit hits). `_SHARED_PROMPT` is the common house-rules system prompt.
- `create_player_model() -> OpenAIModel` — builds the single fixed OpenRouter-backed model shared by all players; temperature 0.1, reasoning disabled, `max_retries=0` (retries are handled by this package, not the SDK client). Side effect: reads `OPENROUTER_API_KEY` from the environment and raises `RuntimeError` if it is missing. No network call here (the client is only constructed).
- `create_player_agents(model=None) -> dict[PlayerName, Agent]` — creates exactly three Strands `Agent`s that share one model instance. Only `PlayerName.ADAPTIVE` receives the two tools (`get_opponent_statistics`, `peek_opponent_card`); the others get none. Each agent uses `structured_output_model=PokerDecision`, `callback_handler=None`, and `retry_strategy=None` (no SDK-level retry). Falls back to `create_player_model()` when `model` is omitted.

### `state.py` — information-isolated visible-state builder
- `_STRATEGY_PROMPTS` — the fixed per-player strategy instruction text (Conservative / Aggressive / Adaptive) appended to the shared prompt.
- `strategy_prompt_summary(player) -> str` — returns the strategy instruction for one player.
- `build_visible_state(state, actor) -> dict` — builds a fresh JSON-compatible dict containing only what `actor` may see: blinds, positions, pot, board, the actor's own hole cards, per-seat public fields (stack, contributions, folded, eliminated), a public action history, and the serialized legal actions. Information isolation: it never includes other players' hole cards. Only if the acting player is Adaptive and a peek observation exists does it attach a deep-copied `peek_observation`. Raises `ValueError` if no hand is active or `actor` is unknown. No mutation of `state`.
- `_serialize_legal_actions(state, actor)` / `_public_action_history(state)` — private helpers that call the engine's `legal_actions` and project only public action-history fields (`seat, player, street, action, amount`), dropping any private data.

### `tools.py` — the two bounded information tools, available only to Adaptive
- `MAX_TOOL_CALLS_PER_ATTEMPT` (2) — cap on tool calls per decision attempt.
- `get_opponent_statistics(opponent, tool_context) -> dict` — Strands `@tool(context=True)`; returns compact public stats (decision counts, per-action rates, aggression frequency, voluntary chips, recent actions) for one opponent read from `state.public_stats`. No state mutation. Gated: returns an `{"ok": False, "error": ...}` dict (not an exception) if the caller is not Adaptive, state is missing, the opponent name is unknown/self, or the per-attempt call limit is reached.
- `peek_opponent_card(opponent, tool_context) -> dict` — Strands `@tool(context=True)`; reveals one of an opponent's two hole cards, chosen reproducibly via `random.Random(state.peek_seed)`. Side effect / one-shot: on success it sets `state.peek_available = False` and stores `state.adaptive_peek_observation`, so it can succeed only once per tournament; later calls return an `ok: False` error dict. Also error-guards non-Adaptive callers, eliminated targets, no active hand, and wrong hole-card count.
- `_adaptive_state(...)`, `_reserve_tool_call(...)`, `_record_tool_event(...)`, `_tool_error(...)` — private helpers. `_reserve_tool_call` enforces the per-attempt cap and increments `tool_call_count`; `_record_tool_event` appends a sanitized event to `tool_context.invocation_state["tool_events"]` for telemetry.

### `schemas.py` — decision result/attempt records and categorized errors
- `StructuredDecisionError(ValueError)` — model output missing/invalid against the structured contract; `category = "structured_output"`.
- `PokerDecisionValidationError(ValueError)` — a typed proposal failed engine validation; carries `errors` and `legal_actions`; `category = "poker_validation"`.
- `PlayerProviderStreamError(ConnectionError)` — a provider-stream failure; treated as transient by the coordinator.
- `InvocationResponse` (dataclass) — `result: AgentResult`, `tool_events`, `tool_call_count` from one player-agent invocation.
- `DecisionAttemptRecord` (dataclass) — sanitized per-attempt record: `attempt`, `category`, `error`, `proposal`, `tool_events`, `tool_call_count`, `usage`, `retry`, `prompt`.
- `DecisionOutcome` (dataclass) — final coordination result: `decision` (or `None`), `attempts`, `used_fallback`, `api_failed`, `visible_state`, `legal_actions`.
- `InvokeOnce` — type alias `Callable[[str, int], AgentResult | InvocationResponse]` for the "invoke one attempt" callback the coordinator drives.

### `validation.py` — structured parsing, poker validation, execution, and fallbacks
- `parse_and_validate_decision(state, actor, proposal) -> PokerDecision` — extracts `structured_output` from an `AgentResult` (or accepts a raw payload), validates it into `PokerDecision`, then runs the engine's `validate_action`. Raises `StructuredDecisionError` when output is missing (including limit stop reasons) or malformed, and `PokerDecisionValidationError` (with legal actions attached) when the ACTION field or the poker rules are violated. Does NOT mutate poker state.
- `build_correction_message(error) -> str` — builds the retry hint containing the failure text plus exact current legal actions (JSON).
- `execute_validated_decision(state, actor, decision) -> None` — calls the engine's guarded `apply_action` after proposal validation and writes the decision's concise `reason` onto the last public action-history entry. Asserts a public action record was created.
- `normalize_usage(result) -> dict` — reads observed Strands token usage; returns an all-`None`/`usage_available=False` shape when metrics are absent or incomplete (never estimates).
- `_fallback_decision(state, actor) -> PokerDecision` — deterministic recovery: prefer CHECK, else FOLD, else exact CALL; asserts if none is legal.
- `_api_fallback_decision(state, actor) -> PokerDecision` — prefers FOLD after API failure, otherwise defers to `_fallback_decision`.
- `_mark_api_failure(state, actor, attempts) -> None` — side effect: sets `state.status = FAILED`, records `state.failure`, and appends a `tournament_failed` event.
- `_structured_correction_message`, `_invocation_parts`, `_proposal_record`, `_validation_legal_actions` — private helpers (correction text for structured errors; unpack `AgentResult` vs `InvocationResponse`; dump a proposal; serialize legal actions).

### `coordinator.py` — bounded retry loop, failure categorization, action execution
- `coordinate_decision(state, actor, invoke_once, telemetry_client=None) -> DecisionOutcome` — the orchestrator. Builds the visible state once, snapshots legal actions, then loops up to `MAX_DECISION_ATTEMPTS` (6) times calling `invoke_once(prompt, attempt)` (the LLM call), parsing and validating each result. Each attempt is wrapped in `player_attempt_scope`/`player_decision_scope` observability spans. Error handling per attempt:
  - transient API errors (`RateLimitError`, `APITimeoutError`, `APIConnectionError`, `InternalServerError`, `ModelThrottledException`, `PlayerProviderStreamError`) → category `api_failure`, increments `state.counters["api_failures"]`, appends a `decision_api_failure` event, resets prompt, retries;
  - `MaxTokensReachedException` and structured/validation errors → append a correction to the prompt and retry.
  On success it executes the decision via `execute_validated_decision` (state mutation) and returns a `DecisionOutcome`. After the loop is exhausted: for `api_failure`, executes a one-time API fallback (fold-preferring) the first time and returns `used_fallback=True`, otherwise calls `_mark_api_failure` and returns `api_failed=True` with `decision=None`; for any other category, executes a deterministic fallback and returns `used_fallback=True`. Side effects: appends to `state.events`, updates `state.counters`, mutates poker state on execution, and emits observation updates.

### `dispatch.py` — direct, bounded single-attempt dispatch to one player agent
- `invoke_player_once(agents, state, actor, prompt, attempt) -> InvocationResponse` — runs one bounded attempt for the acting player by invoking its Strands `Agent` directly (`agent(prompt, invocation_state=..., limits=PLAYER_INVOCATION_LIMITS)`); the acting seat is always known before the call, so there is no routing graph. Network/LLM call. Builds `invocation_state` that passes the live `TournamentState` only for Adaptive (so tools can access it) and initializes `tool_events`/`tool_call_count`. Maps a bare `APIError` and wrapped transient `EventLoopException`s (`APIConnectionError`, `APITimeoutError`, `InternalServerError`, `RateLimitError`, `ModelThrottledException`) into `PlayerProviderStreamError`; other event-loop errors propagate. Side effect: deep-copies and restores `agent.messages` in a `finally` (each decision is stateless across attempts).
- `_WRAPPED_TRANSIENT_ERRORS` — the transient-error tuple unwrapped from the Strands event loop.

### `__init__.py` — public API surface
- Re-exports the package's public functions, classes, and constants (config constants, `create_player_model`/`create_player_agents`, `coordinate_decision`, `invoke_player_once`, schemas/errors, the state builders, the two tools, and the validation helpers) via `__all__`.

## How it fits together
A single decision starts at `coordinate_decision(state, actor, invoke_once)`. It first calls `build_visible_state` to produce the strictly information-isolated view (own hole cards plus public data only; opponents' cards are never exposed, and a peek observation appears only for Adaptive) and serializes it as the prompt. It then drives up to six attempts through the `invoke_once` callback, which in practice is `invoke_player_once`: the acting seat is already known, so it invokes that player's Agent directly under fixed per-invocation limits and returns structured `PokerDecision` output. Each result passes through `parse_and_validate_decision`, which enforces the structured-output contract and then the engine's `validate_action` against the current legal actions. A structured or poker-validation failure appends a correction (with the exact legal actions) to the prompt and retries; transient API/stream/timeout failures retry with the plain prompt. On the first valid decision, `execute_validated_decision` applies it to the engine and records the public reason. If all attempts fail, the coordinator recovers deterministically: a fold-preferring one-time API fallback (then a hard `tournament_failed` mark on a second API exhaustion) or a CHECK→FOLD→CALL deterministic fallback. The Adaptive tools are gated at two levels: only Adaptive agents are constructed with them (`create_player_agents`), and each tool re-checks `invocation_state["actor"]`, requires the `TournamentState` (passed only for Adaptive), and enforces `MAX_TOOL_CALLS_PER_ATTEMPT`; `peek_opponent_card` additionally consumes a single per-tournament `peek_available` flag.
